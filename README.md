# switchbuf — 交换机共享缓冲区仿真与调优工具

面向数据中心"几十兆共享缓冲 + 多对一微突发"场景的仿真工具:
微秒级时间步仿真报文进出队列, 对比共享缓冲分配策略, 按流量组成推荐参数,
并从秒级监控数据反推微突发。

## 快速开始

```bash
python3 run_demo.py demo    # 单场景: 4 种策略对比 + 缓冲占用/门限/丢包三联图
python3 run_demo.py grid    # 验收: 突发规模 x 大流占比 网格, 4 策略对比表
python3 run_demo.py infer   # 微突发推断: 秒级统计 -> 检出率/规模误差
python3 run_demo.py all     # 全部
```

输出在 `out/`: `dynamics_*.png`(每队列占用/动态门限/丢包时刻)、
`grid_results.{csv,md,png}`(策略对比)。

## 模型

**交换机** (`switchbuf/config.py: SwitchConfig`)
- 6 个端口, 速率不同 (10/25/25/40/100/100 Gbps), 可改
- 32 MB 共享缓冲, 所有端口共享; 每端口 3 个优先级队列:
  HIGH=时延敏感小请求, MID=微突发, LOW=大流; 严格优先级调度
- 时间步 1 µs; 丢包按固定 RTO(1ms)重传, 超 7 次判请求失败

**流量** (`switchbuf/traffic.py`)
- 微突发(incast): K 台服务器(默认 32)在 ~50µs 抖动内同时向一个端口
  各发 1 MB(25Gbps 下持续 ~330µs), 超量 = K·S − C·τ
- 大流: 流体建模。背景大流按端口利用率恒定速率; `greedy_elephant_ports`
  上的贪婪大流以 1.3 倍端口速率发送, 持续试图占满共享缓冲(模拟瓶颈
  链路上的 TCP 大流)——这是"缓冲被大流吃光、突发没地方放"的来源
- 小请求: 泊松到达, 1.5–12 KB, 记录每请求端到端时延

**共享策略** (`switchbuf/policies.py`)
| 策略 | 准入规则 |
|---|---|
| `static` 静态均分 | 每队列硬上限 = B / 队列数 |
| `cs` 完全共享 | 总占用 < B 即放行 |
| `dt` 动态门限 | 队列上限 = alpha[prio] × 当前空闲缓冲; 占用低于保留缓冲时总放行 |

**参数推荐** (`switchbuf/recommend.py`)
- 突发超量 E = K·S − C·τ; DT 平衡态单队列上限 ≈ alpha·free/(1+alpha),
  故 `alpha_mid = E / (空闲池 − E)`(装不下时取上限并告警)
- HIGH 保留缓冲 = 突发排干时间内小请求到达量 × 安全系数; alpha 给大(8)
- LOW alpha 给小(0.5), 防止贪婪大流挤占共享缓冲

**微突发推断** (`switchbuf/infer.py`)
只有每端口每秒的发出字节和丢包计数时:
- 检出: 窗口内有丢包 且 平均利用率 < 70% ⇒ 微突发(利用率不高却丢包,
  只能是瞬时打满缓冲); 持续拥塞(利用率 ~100% 带丢包)不误报
- 规模: 估计超量 ≈ 丢包字节 + 缓冲吸收量(≈共享缓冲总量)
- 与仿真 ground truth 对照, 输出检出率/误报率/规模估计相对误差。
  局限: 被缓冲完全吸收(无丢包)的突发从秒级统计不可见。

## 验收指标

`run_demo.py grid` 在 突发规模 K ∈ {8,16,32} × 大流占比 {10%,30%,50%}
下对比 static / cs / dt(平系数) / dt(推荐参数):
- 三类流量各自的丢包率
- 突发流完成时间(FCT)均值/p99
- 小请求时延 p50/p99/p99.9
- 缓冲区峰值/均值占用

`run_demo.py infer` 输出微突发检出率、误报率、规模估计误差。

## 一次验收结果快照(默认参数, 32MB 共享缓冲)

突发丢包率(静态均分 / 完全共享 / DT平系数 / DT推荐):

| K(发送台数) | 大流占比 | static | cs | dt_flat | dt_reco |
|---|---|---|---|---|---|
| 8  | 10–50% | 19.7% | 1.2–1.5% | **0%** | **0%** |
| 16 | 10–50% | 48.4% | 19.5–32.3% | 9.9–13.9% | **0%** |
| 32 | 10%    | 71.1% | 48.1% | 43.1% | **8.9%** |
| 32 | 50%    | 71.1% | 59.0% | 46.0% | **11.7%** |

突发 FCT 均值: K=32 时 static 6.4ms / cs 3.5–4.3ms / dt_flat 2.8–3.4ms /
dt_reco **2.7ms**; K=8 时 dt_reco 0.69ms vs static 1.36ms。
小请求 p99 全部策略约 9µs(HIGH 优先级 + 保留缓冲生效)。
峰值占用: cs 长期顶满 33.5MB(贪婪大流占满), dt_reco 只在突发时到 32.8MB。

微突发推断(3s 仿真, 20 次 incast, 1s 监控窗口):
**检出率 100%, 误报率 0%, 规模估计相对误差中位数 19.1%**。
受害端口利用率仅 ~37% 却被正确检出; 贪婪大流端口(利用率 100% 持续丢包)
未被误报为微突发。

## 文件

```
switchbuf/
  config.py       交换机/流量/策略配置
  traffic.py      流量生成(NumPy 向量化)
  policies.py     三种共享策略准入控制
  engine.py       微秒级时间步仿真引擎
  recommend.py    按流量组成推荐保留缓冲和门限系数
  infer.py        秒级统计 -> 微突发推断
  experiments.py  验收网格实验
  plots.py        可视化
run_demo.py       端到端入口
```
